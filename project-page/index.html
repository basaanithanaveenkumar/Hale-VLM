Problem Statement

Strong text-only LLMs (Qwen3, DeepSeek-R1) are capable reasoners but have no visual grounding. Adding vision capability typically means one of:

Full fine-tuning: Expensive, risks catastrophic forgetting of language capabilities, requires large cluster. Impractical for independent research.
CLIP + simple projection: Works for captioning and basic VQA but misses the chain-of-thought, code, and math reasoning the dense LLM backbone provides.
Adapter-only (LoRA without projector): The LLM's token space is not designed for raw image patches; a trainable projector is needed to bridge the two modalities.

The Hale-VLM design targets a middle path: freeze everything except a small learned bridge (projector + LoRA) — the LLM retains all its reasoning ability while gaining the ability to interpret images. Reproducibility is a first-class concern: the full SmolVLM data recipe is encoded as typed Python specs, not scattered shell scripts.

Method

  1. Vision tower

    SigLIP-B/16 (12-layer ViT, patch size 16, output dim 768) processes 224×224 images without the [CLS] token — all 196 patch embeddings are kept and fed to the projector. The encoder is frozen throughout training.

  2. MLP projector

    A two-layer MLP with GELU activation maps 768-d SigLIP features to the LLM's hidden dimension $d$: $\text{proj}(z) = W_2 \cdot \text{GELU}(W_1 z)$ where $W_1 \in \mathbb{R}^{2d \times 768}$ and $W_2 \in \mathbb{R}^{d \times 2d}$. This is always trainable and accounts for ~40M parameters (Qwen3-8B).

  3. LoRA adapters

    LoRA rank 16 is applied to q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, and down_proj in every transformer layer of the LLM. Each adapter adds $\Delta W = BA$ where $B \in \mathbb{R}^{d \times r}$, $A \in \mathbb{R}^{r \times d}$, $r=16$. Only $A$ and $B$ are updated; the base weight is frozen.

    ★ Parameter efficiency: Qwen3-8B has ~8B parameters. LoRA (43.6M) + projector (39.9M) = 83.5M ≈ 1.0% trained. DeepSeek-R1-Distill-7B: 71.6M ≈ 0.9%.

  4. Streaming data pipeline

    The SmolVLM recipe defines 19 datasets across three stages (vision, video, long-context). A SequentialMultiDatasetStream plays each dataset up to a configurable cap while pre-fetching the next in a background thread — bounded disk usage regardless of total dataset size.

    540 SmolVLA robot datasets can be converted to VLM samples via vla_sample_to_vlm() in three modes: pretrain (image+caption), finetune (Q&A), and instruction (trajectory description).

  5. Training & registry wiring

    Every component (model variant, loss, trainer, datasets) registers into HaleBlocks via a decorator. A YAML config selects components by name. inherits: base.yaml allows single-field overrides without duplication.

    Training uses causal LM loss on answer tokens only (prompt tokens masked with $-100$). AdamW, AMP (bfloat16), configurable gradient accumulation.

Demo & Quick Start

  1. git clone https://github.com/basaanithanaveenkumar/Hale-VLM && cd Hale-VLM
uv sync --extra dev
  2. # Train on SmolVLM full mixture (streams from HuggingFace Hub)
uv run hale-vlm-train configs/smolvlm_all.yaml
  3. # Interactive chat with a saved checkpoint
uv run hale-vlm-chat configs/base.yaml \
  --image path/to/photo.jpg \
  --prompt "Describe what is in this image in detail."

Limitations & Ethical Considerations

Bug — fixed

Visual token overwrite

Visual tokens currently overwrite text tokens after <image> instead of inserting before them. Fix documented in known-issues.md.

Bug — fixed

Loss on full prompt

Loss currently covers prompt tokens as well as answer tokens. Should be masked to answer-only to match standard VLM training.

Pending

No benchmark scores

VQAv2, TextVQA, GQA, and MMBench evaluations have not been run. Both bugs above should be fixed first.

Open

Bias in visual grounding

SigLIP was trained on web-scale data with known demographic biases. Robotic deployment on real-world scenes requires careful evaluation of failure modes on diverse environments and objects.

Compute

Training cost

Streaming 8B-parameter models with LoRA still requires ~24 GB GPU RAM. SmolVLM full mixture has hundreds of millions of samples; most users will cap at 1K–10K per dataset.
