Hale-VLM: Parameter-Efficient VLMs on Dense Reasoning LLMs

A frozen SigLIP encoder and a small MLP projector connect to Qwen3-8B or DeepSeek-R1-Distill-Qwen-7B, which are adapted with LoRA. Experiments are one YAML file, and the full SmolVLM and SmolVLA data recipes are typed registries.

TL;DR. Train about 1% of an 8B model (LoRA + projector) to give it vision. Every piece (model variants, loss, trainer, 19 SmolVLM datasets, 540 SmolVLA robot datasets) is a HaleBlocks plugin, and robot frames can be reused as VLM training data.

Abstract

Turning a strong text-only LLM into a vision–language model is conceptually simple: connect a pretrained image encoder through a small projector and fine-tune. In practice, most effort goes into the surrounding system: which parameters to train, how to express multi-stage data mixtures reproducibly, how to stream tens of large datasets without exhausting disk, and how to reuse robotics data.

Hale-VLM builds VLMs on Qwen3-8B and DeepSeek-R1-Distill-Qwen-7B from a frozen SigLIP encoder, a trainable MLP projector and LoRA adapters, updating about 72–84M parameters. Every component is a plugin in the HaleBlocks registries, so a whole experiment is one inheritable YAML file. The framework ships typed registries of the SmolVLM recipe (19 datasets by stage, plus one documented rejected dataset) and the SmolVLA robotics corpus, a bounded-storage streaming mixer, and a converter that turns robot frames into VLM samples.

Highlights

≈1% trainable

SigLIP and LLM frozen. MLP projector plus LoRA r = 16 on q,k,v,o,gate,up,down: 83.5M for Qwen3-8B, 71.6M for R1-Distill-7B.

Two reasoning backbones

Qwen3-8B (default) and DeepSeek-R1-Distill-Qwen-7B through transformers, with a custom backbone option.

Registry-driven

Model variants, loss, vlm trainer and datasets register into HaleBlocks. Configs use strict schemas with inherits:.

SmolVLM recipe as code

Vision, video and long-context stages as typed dataset specs. SmolTalk is registered but disabled, with the paper's reason attached.

Bounded-storage streaming

Stream one dataset at a time up to a cap while the next is warmed up in the background.

Robots → VLM data

534 community, 2 simulation and 4 real-world SmolVLA datasets, convertible into pretraining, fine-tuning or instruction samples.

Status and known issues

No benchmark results are reported yet. Two input-pipeline issues were found while writing the paper: visual tokens currently overwrite the text after <image>, and the loss covers the whole prompt. Both are documented with fixes in known-issues.md and should be fixed before benchmarking.

Quick start

git clone https://github.com/basaanithanaveenkumar/Hale-VLM && cd Hale-VLM
uv sync --extra dev
uv run hale-vlm-train configs/qwen3_8b_overfit.yaml
uv run hale-vlm-chat configs/base.yaml --image cat.jpg --prompt "What is in this image?"
# configs/smolvlm_all.yaml — the full SmolVLM mixture
inherits: base.yaml
data:
  source: registry
  registry_stage: all
  streaming: true
  max_samples_per_dataset: 128
